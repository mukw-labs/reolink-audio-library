These results were recorded on 2026-11-02. The lightweight skips are HA-only
coverage; its existing pytest-asyncio fixture-loop warning remains. An isolated
process in an actual HA 2026.9.0 / Python 3.14.6 container also imported all new
modules and validated all four action schemas and selectors without installation
or camera access.

Coverage includes real-library AES/TCP handling with fake cameras, pinned
transport, ACK correlation and status, owned-session cleanup, capacity/profile
checks, byte/metadata preservation and independent-session verification. Rename
and delete tests exercise stale selection, UUID reuse, factory protection,
configured automatic replies, name validation, single mutation attempts, lost
ACK reconciliation, cancellation and uncertain outcomes.

Real HA harnesses cover config/options flow, device and media selectors,
administrator permissions, delete confirmation, response handling, status/capacity
updates and coexistence with foreign Talk services and entity identities.
Preview coverage includes bounded cache invalidation across camera aliases,
authenticated GET/HEAD/ranges and signed media URLs. Synthetic codec vectors,
bounded FFmpeg conversion and local self-signed HTTPS are tested offline.

## Physical backend validation

On the exact supported WiFi-W profile, the approved 0.2.0 test created one new
0.1-second silent recording, renamed it, exported identical audio before and
after, and deleted only that new recording. Both inventories matched the baseline
afterwards. A further read-only session confirmed the temporary ID/UUID were gone
and automatic-reply settings were unchanged. Nothing played on the camera.

See [management validation](RENAME_DELETE_VALIDATION.md) for the scope and limits.
The physical check exercised production backend functions in a separate process;
the HA action boundary was exercised by software harnesses. It was not a camera
power-cycle test or a deployed standalone UI test.

The public release adds documentation, PNG branding and corrected HA manifest
metadata to the physically tested backend. Its Python implementation is
byte-identical to that tested source.
Release archives contain the integration, branding, license and notice; private
operator scripts, firmware, captures and hardware evidence are excluded. Each
release includes a SHA-256 sidecar generated by `scripts/build_release.py`.
